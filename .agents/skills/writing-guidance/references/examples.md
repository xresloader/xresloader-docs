# 改写与保留示例

以下均为教学用假设材料，不代表 xresloader 工具行为或已执行检查。实际修改前核对对应实现、原稿和记录；完整语义规则见 [writing-rules.md](writing-rules.md)。

## 动作不能靠修饰词替代

原句：

> 通过补强超时兜底链路，全面赋能系统稳定性。

若已知实现只增加超时清理，可写：

> 请求超时后，服务会清理等待队列中的对应记录。

不能补成自动重试或整体稳定性提升，也不能为删除“高效”编造性能数字。

英文原句 `The module facilitates the seamless orchestration of configuration validation.` 在已知启动时检查配置的前提下，可写 `The module validates the configuration at startup.`；若未确认时机，不能新增 `at startup`。

## 数量、条件与状态

| 已知材料 | 可用表达 | 会改变含义的表达 |
| --- | --- | --- |
| 总尝试次数最多 3 次，包含首次调用 | 总共最多尝试 3 次；首次失败后最多再重试 2 次 | 最多重试 3 次 |
| 要求版本不低于某个已核验版本 | 保留原版本值及“不低于” | 改成“建议使用”或“高于” |
| 没有运行代码示例，只完成站点构建 | 站点构建通过，代码示例未运行 | 示例验证通过 |
| 缺少真实输入样本 | 缺少真实样本，对应行为尚未验证 | 验证失败或不支持 |
| 任务结束可包括成功、失败或取消 | 按对象写结束状态，保留 `isTerminal` | 一律改成成功完成 |

这些示例的数字或状态来自假设材料，不能据此修改实际项目参数和记录。

## 保留作者判断

假设原稿：

> 我暂时不想接这套方案。每次升级都要改调用方，维护成本太高。

需要解释判断范围时可写：

> 我暂时不采用这套方案：目前每次升级都要改调用方，这个维护成本我接受不了。

不应自动改成“该方案具备一定价值，但仍存在进一步优化空间”。是否保留“不想接”取决于原稿语气；不添加作者未提供的经历或情绪。

## 对举、转折与递进

| 原句与材料 | 处理方式 |
| --- | --- |
| 本节不是罗列功能，而是介绍配置步骤；上下文无需纠正章节范围 | 可直接写“本节介绍配置步骤” |
| 性能和兼容性都有问题，当前先修兼容性，却写“问题不在性能，而在兼容性” | 写“性能和兼容性都存在问题，当前优先处理兼容性” |
| 本工具不仅能扫描日志，更能生成报表；两项都已确认 | 可写“本工具能扫描日志并生成报表”，保留两项事实 |
| 这里统计的不是请求次数，而是消息条数；读者容易混淆二者 | 保留真实的区分 |
| 调用成功，但日志未完整写入 | 保留正常转折，两项可以同时成立 |

“不是 A，而是 B”属于并列中的对举，否定 A；“不仅 A，而且 B”保留 A。不能机械换连接词或删除递进前项。

## 应当保留的表达

- “训练损失尚未收敛”：准确描述算法性质。
- “这个接口返回视图，不复制数据”：说明真实的行为区别，前提是实现已核验。
- “先关闭连接，再释放缓冲区”：必要的先后顺序。
- “错误预算已用完”：上下文已定义 SRE 错误预算。
- “她一直没有说出那个秘密”：普通叙事词义。
- “现有证据不足以支持这个因果结论”：讨论支持材料与结论。
- “重复确认目标目录后再删除”：必要操作提醒，不能为避免重复删掉。
- 原始日志、引文、`Secret` 类型、选项名和配置键：不因命中词表修改。
