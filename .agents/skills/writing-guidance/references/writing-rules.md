# 写作详细规则

本文件是本仓库写作规范的详细规则；简版流程见 [SKILL.md](../SKILL.md)，改写反例见 [examples.md](examples.md)。根据用户指定的 AI 写作指南改编，来源版本、核验范围与更新条件见 [来源索引](../../../../docs/ai/source-index.md) 的写作规范记录。使用本 Skill 不需要访问外部笔记路径。

按任务读取相关章节：事实与声音、结构与句式、语义用词、技术文本与本站格式、交付与维护。以下是编辑建议，不能用来鉴定作者或保证检测分数。

## 事实、读者与作者声音

面向新手解释必要背景和首次出现的术语；面向熟悉领域的读者写清新问题、前提和取舍，省去基础知识复述。篇幅由内容与用途决定，单句修改不扩成全文重写。

数字、单位、日期、版本、平台和实验条件与材料一致。易变事实核对当前一手资料，推断明确标注；相关性不能写成因果，“可能”不能写成“必然”，局部支持不能写成全面兼容。限制落到具体条件，不在每句堆叠“可能也许”。

引用紧邻它支持的断言，核对原文是否支持该说法。引文保留措辞，转述与译文补充解释分别标明；不使用真实链接装饰无依据结论。真实案例、作者经历与虚构教学示例分开，虚构创作遵循任务约定。

保留作者的第一人称、具体观察、犹豫、有依据的负面评价和偏好；主观判断明确归属于作者。不要把尖锐但有依据的批评自动改成中性套话。需要校准文风时，抽样读作者指定的同类作品，记录背景、举例和判断的表达习惯；不移植旧文章的事实或固定口头禅。没有样本时不声称已还原作者风格。

## 结构与句式

| 文本用途 | 可选组织方式 |
| --- | --- |
| 决策、选型、工作说明 | 判断或行动 → 依据 → 条件与代价 |
| 教程、操作说明 | 目标与前提 → 步骤 → 预期结果 → 必要排错 |
| 排障、实验复盘 | 现象 → 实际记录 → 排除过程 → 原因 → 验证 |
| 原理推导、学习笔记 | 问题 → 必要概念 → 推导 → 适用条件 |
| 评论、博客、随笔 | 跟随论点、观察和叙事推进 |

这些顺序按理解需要选用，不是固定模板。正式摘要、必要回顾、操作提醒和指定章节保留；不强凑第三点、相同长度的小节或每节小结，不为结论前置破坏推导。

段落围绕一个主要问题展开，句子有真实联系；标题对应主题变化。列表适合步骤、并列项与检查表，表格适合比较或字段映射，论证与叙事用自然段。没有统一句数或字数要求，不把连贯解释切成碎句。

| 句式 | 语义与改写边界 |
| --- | --- |
| 既 A，又 B | 并列中的平列；A、B 都成立 |
| 不是 A，而是 B | 并列中的对举；否定 A、肯定 B；这里的语法分类不表示两项都成立 |
| A，但 B | 转折；A 仍成立，B 说明限制或与预期不同的情况 |
| 不仅 A，而且 B | 递进；A 仍成立，简化时保留两项事实 |

否定项只为烘托重点时直接陈述；纠正误解、区分概念和说明排除范围时保留。不虚构反面观点，不把可同时成立的两项写成互相排斥，不只换“而是”为“但”或“更”掩盖关系错误。正常因果、转折、让步和先后连接词按实际关系使用，不设次数或比例限制。

主语靠近谓语，条件靠近它限制的动作。先检查指代、施事、多层定语和真实逻辑，再决定拆句；中文自然省略主语和有用途的被动句可以保留。英文避免无必要的名词化和连续分词结构，译文按目标语言组织语序。术语、缩写、大小写、单位、间距及标点遵循目标文本约定，不禁用某种标点。

比喻应降低理解成本，说明技术对应关系及边界。删除无信息的意义拔高与自我评价，不把局部修复写成全面解决。作者有意的称呼、后记、幽默和必要披露按文体保留；正文去掉“当然可以”“下面为你”等助手包装。

## 用词按语义判断

下面是复核线索，命中不表示必须修改。改写前确认对象与行为；准确专业术语、引文、代码标识符和普通叙事中的词义保留。同一对象不要为了变化措辞轮流叫缓存、副本、投影和视图。

| 表达 | 空泛或歧义时怎样写清楚；需要保留的含义 |
| --- | --- |
| 补强 | 写修复对象、补充检查或新增测试 |
| 投影 | 核对是缓存、副本还是派生视图；数学、数据库与图形投影保留 |
| 水位 | 写最大值、阈值、已处理序号或当前占用量；定义明确的 watermark 保留 |
| 预算 | 区分总尝试次数、剩余重试次数、时长或剩余时间；财务、SRE 错误预算和资源预算保留 |
| 终态、终值 | 任务写结束状态，数据写最终值/状态/快照，事务写最终决议；正式概念及 `isTerminal` 保留，结束可包括失败或取消 |
| 合同 | 软件语境按对象写设计规范、接口约定、字段规则、平台协议或验收标准；法律合同、引文与标识符保留 |
| 缺证、待证、未证 | 写缺少什么材料或尚未完成什么检查；未验证不能写成不支持 |
| 证据 | 研发说明具体写源码依据、文档依据、样本、日志、测试、测量或验证记录及其支持的结论；法律取证与讨论证明材料时可保留 |
| 门槛 | 写前置/采用条件、版本要求、验收标准或判定阈值；保留强制与参考、版本及比较方向，实际进入难度可用原词 |
| 赋能、加持 | 写谁能完成什么；引文或有意文体按需保留 |
| 抓手、底座 | 写方法、工具、公共库、运行时或服务及职责 |
| 打通、链路 | 写连接对象、数据流向或调用顺序；网络链路与链路追踪保留 |
| 沉淀、落地 | 区分记录、持久化、提取公共代码、实现与部署 |
| 闭环 | 写实际步骤与完成条件；闭环控制等正式概念保留 |
| 对齐、拉齐 | 写按什么规则修改、哪些字段一致；内存、序列和模型对齐保留 |
| 收敛 | 写合并、统一状态或缩小范围；算法与状态收敛保留 |
| 口径 | 写计算规则、统计范围和时间来源，多个规则分别说明 |
| 维度、颗粒度 | 写指标、条件或处理单位；张量与空间维度保留 |
| 兜底 | 写触发条件及重试、默认值、拒绝或清理的实际行为，不能互换 |
| 护栏、门禁 | 写参数/权限/发布前检查及阻断条件；已定义的专门含义保留 |
| 钳制 | 写限制范围与超限行为；控制、电路与数值计算术语保留 |
| 重新武装定时器 | 按接口语义写重设到期时间、重启或再次注册，不能擅自改成新建 |
| 秘密、机密 | 安全上下文区分密钥、凭据、口令与敏感信息；Secret 类型、标识符和普通叙事按原义保留 |
| 夹具 | 静态文件可写测试数据或样本；泛指固定测试前提时保留 fixture 或项目准确术语 |

“值得注意的是”“事实上”没有实际提醒或对比时删去；“显然”“毋庸置疑”不能替代理由。“本质上”“系统性”需要机制或范围，“无缝”“高效”“稳健”需要能力、条件或测量。删除夸大词时不能编造性能数字，具体机制也要有实现依据。

`delve`、`leverage`、`robust`、`seamless` 等英文词按含义、频率与读者判断，不按词表批量替换。定义、角色与动作选合适句式，不机械把 `is` 改成 `serves as`。英文 `not X but Y` 和 `not only X but also Y` 分别复核否定与递进关系。

## 技术文本与本站格式

| 文本位置 | 应写清楚及保护的内容 |
| --- | --- |
| 注释 | 当前实现不易看出的原因、不变量、边界、顺序和取舍，避免逐行复述代码 |
| 文档字符串、接口说明 | 参数/单位、返回、错误、前提和副作用；按需说明并发、所有权、取消，保留标签、类型、签名和运行时读取的字符串 |
| README、教程 | 目标、依赖、步骤、预期结果与必要排错；命令、路径和版本条件必须可核对 |
| 变更说明、PR、提交信息 | 触发问题、行为变化、影响范围与实际验证，不把未执行写成通过 |
| 日志、错误消息、界面文案 | 实际情况与可采取行动；保留错误码、模板变量、解析格式、快照、监控规则和国际化键 |

只检查改动涉及的技术条件：

- 次数是总尝试还是首次失败后的重试，何时增加或重置。
- 时间是截止时刻还是持续时长，单位与时间来源是什么。
- 数值范围是否含端点，缺省、空值与零值是否相同。
- 数据是缓存、独立副本还是实时派生视图，更新是否有延迟。
- 失败时是重试、忽略、返回默认值、报错还是终止，有无副作用。
- 调用是否阻塞；完成、成功、提交、持久化与收到确认是否为不同阶段。
- “必须、应当、建议、可以”及“最多、至少、仅当、除非、包含、不包含”是否保持原有强度与范围。

本仓库额外核对：xresloader/xresconv/代码生成器的职责、输入格式、字段规则、选项拼写、适用版本、导出结果及示例来源。`source/sample/` 的历史生成文件不能证明当前工具行为。没有核验的编码、大小写、空值、默认值或平台差异不能从“通常如此”补入正文。

只改文风时保留标识符、配置键、环境变量、路径、协议原文、测试期望与原始输出；若发现功能或接口约定错误，单独核验和处理。历史验证记录保留当时的日期、版本、命令、结果和未执行项，不能把旧结果更新成当前通过。

示例代码符合目标语言和版本，伪代码及示意值标明性质；没有运行就记录未运行。源码核验、文档依据、合成测试、真实样本和实际运行覆盖不同范围，不能互相替代。区分尚未验证、缺少真实样本和验证未通过。

保留 Docusaurus frontmatter 的 `id`、`slug` 等字段、标题层级、稳定 URL、锚点、引用与资源路径；需要更改时核对调用方和侧栏。自然语言中的 `<...>`、花括号等若影响 MDX 解析，按上下文使用代码标记或转义，不改可执行示例。引文、程序输出与历史日志不做自动用词替换。

技术文章与博客保留有意义的失败过程、实验条件和取舍，不虚构亲身经历。图表用于解释关系、流程、时序或数据，代码与图表前说明所回答的问题，保留关键数值、单位、图注和替代文本；不为装饰添加图表。

## 交付与规则维护

交付前按需复查事实与来源、作者判断、段落关系、术语、否定/数量/时序/因果、验证状态及格式。确认正常术语、真实对比和必要警告没有被误删，正文没有占位文字和编辑批注。让读者能够复述要点、找到依据与行动；文章检查核心观察或判断是否清楚。

来源中的研究核对日期是 2026-09-25；本仓库改编时只读取用户指南，没有重新核验论文，也没有执行多模型对照或读者盲评。词表和编辑办法按工作建议采用，不能称为已验证的中文作者检测方法或普遍有效的模型行为结论。

更换主要写作模型、新增语言/文体、反复误改或来源修订时复核；每 3—6 个月是可选维护频率。先读当前规范、失败样例与来源记录。调研时查一手研究和官方编辑指南，区分正式研究、预印本、编辑经验、观察与推断，记录版本、访问日期、实际阅读范围、语言、模型、任务、限制和反例；多处转述同一研究只算一个来源。

验证候选规则时选代表性原稿、坏例与应保留的正常表达，逐例记录不可改的事实、立场、术语和格式。新写用相同材料，润色用相同原稿，分别比较；保持模型版本、工具和可控制设置一致，记录无法固定的随机性。先查语义，再让目标读者随机顺序比较，单人评审注明限制；跨模型效果需实际复测，不能以升级效果代替规则效果。

调优和留出样本分开，记录偏好、持平、原因与人工返工成本。事实或技术语义退化必须修正，不能用流畅度抵消；不设通用词频、句长或检测器合格阈值。新增规则写适用条件、改法与例外，合并重复或降级误伤规则，同步简版、细则、示例、来源和验证结论。当前规则直接更新，历史由 Git 保存，不在正文追加日期流水账。
