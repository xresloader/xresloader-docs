# AI 工程维护

交付低冗余的共享入口、具体任务流程、可达参考和真实验证记录。先核对根 [AGENTS.md](../../../AGENTS.md)；不复制其全文到其他入口。

## 输入与工作流

1. 初始化/全面维护先完整读取用户输入到结束标记；截断则分段补读。读 Git 状态、适用规则、已有索引、客户端与能力后，在唯一 [覆盖记录](../../../docs/ai/initialization-coverage.md) 登记所有源章节、章内列表/表格/条件和用户补充要求，使用稳定 ID。普通窄修改只更新受影响行。
2. 为每个可独立验收的要求写适用依据、实际文件/章节、状态及证据。已覆盖、不适用、待处理、阻塞分别使用；不适用需范围或项目事实依据。规则落地和真实运行拆行，父项随子项汇总；不删除行来缩小范围。
3. 事实与工具更新先读 [来源索引](../../../docs/ai/source-index.md) 并复核官方正文/实现。写 claim、scope、URL/版本、核验日期/方法、安装版本/状态、复核周期/触发及影响/责任。模板旧日期、摘要和记忆不替代当前核验。
4. 常驻只放高频稳定约束；任务知识写具体 Skill，长资料按需引用。按 [维护规范](references/maintenance.md) 选择承载位置、检查字段/资源/权限/供应链；客户端差异读 [兼容记录](references/clients.md)。完整 [CLI 候选](references/cli-tools.md) 保留所有 31 项及实际探测/回退，不批量安装客户端或可选工具。
5. 按覆盖表从要求查产物，再从产物反查来源；回读正文、差异、相对资源和触发入口，替换全部填空。格式与引用通过不等于实质覆盖；用户附件中的必要内容应变成仓库可达资料，不能留下附件绝对路径作工作入口。
6. 实质描述变化更新 [触发与质量评估](../../../docs/ai/skill-evaluation.md)，使用真实客户端调用轨迹及可比的有/无 Skill 输出。没有实际 harness 运行证据时保留运行子项阻塞。结构验证、预期路由与模型口头承诺都不能写为运行通过。
7. 按 [工程工作流](../../../docs/ai/engineering-workflow.md) 验证 Markdown、引用、Skill 规范及站点隔离；同步入口、索引、来源、覆盖和受影响文档。交付分别统计章节和独立子项，不重复计算；报告产物、运行证据、未完成 ID 及下一步。

## 异常与恢复

联网失败只有限重试；完成不依赖缺失资料的工作，易变结论标未验证。未知客户端不创建占位目录。输入缺失或必需运行条件缺失保留具体阻塞，交付写部分完成。上下文恢复从覆盖记录的当前 ID、证据与授权边界继续。

## 纠错与复核

失败先记录最小复现、原因和实际验证，区分环境、实现、路由与旧资料。会复发的问题优先补确定性检查或对应 Skill；一次手误不膨胀常驻规则。新规则注明触发、范围及失效/复核条件，合并重复项；升级模型、harness 或依赖后用同输入对照评估旧补丁。个人持久记忆只在用户明确授权时更新。

第三方 self-improvement/error-repair/skill-maintenance 候选审计及引用许可按维护规范处理，不把榜单、下载量或单次评价当权威，不安装或执行未审计 bundle。
